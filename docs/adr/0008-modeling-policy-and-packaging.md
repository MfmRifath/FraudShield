# ADR-0008: Modeling, decision policy and model packaging

- Status: Accepted
- Date: 2026-10-23
- Phase: 2

## Context

Phase 2 turns features into an approve/review/block service decision. Several details are open: how to choose boosting rounds without touching val/test, what "rules-only" means as a baseline, how to package a model that serving can load fast and safely, and how to define the metrics.

## Decision

1. **Data use per window:**
   - Boosting rounds come from Optuna CV (`configs/tuned/<ds>.json`), or else from early stopping on the last rolling-origin fold *inside train*.
   - Final models are refit on all of train, calibrated on val, and evaluated once on test.
   - The category vocabulary and the "typical" values for reason codes come from train only.
2. **Models:**
   - `rules_only` (`configs/rules.yaml`);
   - `logistic` (median imputation + missing indicators, scaling, one-hot categorical codes, balanced class weights);
   - `lgbm_degraded` (request-only features, the serving fallback);
   - `lgbm_full`.

   Imbalance is handled by a tuned `scale_pos_weight`; there is no resampling.
3. **Calibration:** isotonic on val; Platt (logistic on the score's logit) if val has fewer than 1,000 frauds; identity if val has a single class. Stored as JSON (thresholds or a, b) and applied with numpy.
4. **Policy:** each decision gets an expected cost from `configs/costs.yaml` and the cheapest wins. A per-UTC-day review capacity keeps the reviews with the largest saving; the rest fall back to the cheaper of approve/block.
   - The rules-only baseline maps fired rules to block/review, and over-capacity reviews (lowest amount first) to approve. Its ranking score is block 1.0 / review 0.5 / none 0.
   - The **cost values are placeholders** chosen to be plausible, not sourced. The evaluation reports a ×0.5/×1/×2 sweep of each parameter.
5. **Metrics:**
   - PR-AUC, ROC-AUC, recall at FPR 0.1/0.5/1 %, Brier, ECE (10 equal-width bins);
   - Card Precision@100: per test day, rank cards by max score, take the share of the top 100 with a fraud that day, then average over days (Fraud Detection Handbook definition);
   - dollars: realized cost, net savings vs approve-all and vs rules-only;
   - segments: *new uid* = no earlier event for the uid in the dataset (`uid_secs_since_last` is null) vs *known*.
6. **Packaging (`model_bundle.py`):**
   - A directory with `full.txt`, `degraded.txt` (LightGBM text models) and `bundle.json` (feature orders, category vocabulary, both calibrators, costs, typical values, reason map, metadata). No pickles.
   - Serving loads it directly. MLflow wraps it as a pyfunc (`FraudShieldPyfunc`) with the bundle as an artifact, registers it, and sets alias `@challenger`.
   - Inference uses `num_threads=1`.
7. **Reason codes:** each feature maps to one of 10 reason groups. Positive `pred_contrib` values are summed per group; the top 3 groups are kept, each described by its largest feature as "label = value (typical X)".
8. **MLflow store:** SQLite + local artifact directory by default (MLflow ≥ 3.13 rejects file stores). The compose `mlops` profile points at the MLflow server with Postgres (Phase 5).

## Alternatives considered

- Pickled sklearn/LightGBM objects via `mlflow.lightgbm` (now skops by default): heavier, slower to load, and a security concern for a service. Rejected for serving; we log text models.
- Calibrating on a slice of train: wastes train data and blurs the val window's role. Val is used for calibration only; early stopping uses an inner train fold.
- A separate registered model for the degraded variant: two registry entries to keep in sync. Bundled together instead.

## Consequences

- Real-data results (comparison table, Card Precision@100, net savings, model card) are generated by `make train` / `make docs` in the deferred real-data session (CLAUDE.md rule 9). Until then only the synthetic smoke test exercises the pipeline.
- mlflow 3.17.2 requires `pyarrow<26`, so pyarrow is pinned to 25.0.1. Phase 1 feature manifests recorded 26.0.0; `features-check` reports this as a version difference (warning), not a content difference.
- LightGBM's macOS wheel needs a system OpenMP runtime (`brew install libomp`). `make test-docker` runs the suite in Linux without it.
